# kupe_database_backup (Resource)

Takes a manual backup of a Kupe database. Create waits until the backup has completed (phase `Completed`) and fails at once if it fails. A backup that fails or times out on create stays in state, marked tainted. Changing `name` or `database` takes a new backup. Set timeouts with the `timeouts` attribute, for example `timeouts = { create = "90m" }` (defaults: create 60m, delete 15m).

A manual backup is kept until you delete it, even after the database is deleted, and a new database can be restored from it with `source.backup` on `kupe_database`. It is deleted with your account. A database can keep up to 20 manual backups. Reading and deleting a backup works even while the Kupe platform has databases or backups switched off.

### Destroy semantics

Destroying this resource deletes the backup: it can no longer be restored from. Deleting a database removes it and its automatic backups immediately, and they cannot be restored. Manual backups stay until you delete them.

## Example Usage

```terraform
# Take a manual backup before a schema migration. It is kept until you delete
# it, even after the database is deleted.
resource "kupe_database_backup" "before_migration" {
  database = kupe_database.orders.name
  name     = "orders-db-before-migration"
}
```

### Restoring from a backup

Restore a backup into a new database with `source.backup` on [`kupe_database`](database.md). The new database runs `source_version` and needs at least `source_storage`. The backup is unchanged and can be restored from again.

### Keeping a backup after its database

A manual backup stays when its database is deleted, and `database_deleted` reads `true` from the next refresh. In one configuration a backup usually refers to its database, as in `database = kupe_database.orders.name`. Before you remove the database from the configuration, set `database` to the name itself (`database = "orders-db"`). The value is the same, so the backup is not replaced.

`terraform destroy` deletes every backup in the configuration along with everything else. To keep a backup, remove it from the state first, for example `terraform state rm kupe_database_backup.before_migration`.

## Schema

### Required

- `database` (String) Name of the database to back up. It must be running. Changing it takes a new backup.

### Optional

- `name` (String) Backup name: lowercase letters, digits and `-`, starting and ending with a letter or digit, at most 63 characters. When unset, the Kupe platform names the backup after the database and the time, in UTC, for example `orders-db-20261030-141500`. Changing it takes a new backup.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `completed_at` (String) When the backup finished (RFC 3339). Empty until it completes.
- `created_at` (String) Timestamp when the backup was created.
- `database_deleted` (Boolean) True once the database the backup was taken of is deleted or being deleted. The backup stays until you delete it.
- `phase` (String) The backup's state: Pending, Running, Completed, Failed or Deleting. `Completed` once it can be restored from.
- `size_bytes` (Number) Size of the backup in bytes. 0 until measured.
- `source_storage` (String) Storage the database had when the backup was taken. A database restored from the backup needs at least this much. Empty until the backup starts.
- `source_version` (String) PostgreSQL major version of the database when the backup was taken. A database restored from the backup runs this version. Empty until the backup starts.
