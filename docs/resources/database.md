# kupe_database (Resource)

Manages a Kupe managed PostgreSQL database. Create and Update wait for the database to reach phase=Running with the change applied; Delete waits until the database is gone. Timeouts are configurable via the `timeouts` block (defaults: create/update 30m, delete 15m).

Applications reach the database through `kupe_database_binding`, which places a Service and a credentials Secret in one namespace of one cluster. Credentials are never returned by the API or stored in Terraform state.

### Destroy semantics

Deleting a database deletes its data. `deletion_protection` (default `true`) makes the Kupe platform refuse the delete: set it to `false` and apply before destroying. Add `lifecycle { prevent_destroy = true }` to stop Terraform from planning the destroy at all.

## Example Usage

```terraform
resource "kupe_database" "orders" {
  name    = "orders-db"
  version = "18"

  resources = {
    cpu     = "500m"
    memory  = "1Gi"
    storage = "10Gi"
  }

  # Two instances with a synchronous standby. Can be turned on or off later.
  high_availability = true

  # deletion_protection defaults to true: the platform refuses to delete the
  # database until it is set to false and applied.
}
```

### Protecting a database from destroy

`deletion_protection` makes the Kupe platform refuse the delete. `prevent_destroy` stops Terraform from planning it in the first place, so use both for databases you cannot lose.

```terraform
resource "kupe_database" "billing" {
  name = "billing-db"

  resources = {
    cpu     = "1"
    memory  = "2Gi"
    storage = "50Gi"
  }

  # Stop Terraform from planning a destroy at all, on top of the platform's
  # deletion protection.
  lifecycle {
    prevent_destroy = true
  }
}
```

To delete a protected database, set `deletion_protection = false` (and remove `prevent_destroy`), run `terraform apply`, then destroy it.

### Connecting applications

Grant access with [`kupe_database_binding`](database_binding.md). Each binding places a Service named after the database and a credentials Secret into one namespace of one cluster.

### Optional

- `deletion_protection` (Boolean) While `true`, the Kupe platform refuses to delete the database. Set it to `false` and apply before destroying. Default `true`.
- `engine` (String) Database engine. Only `postgres` is supported, and it is the default. The engine of an existing database cannot change: a different value fails the plan instead of replacing the database.
- `high_availability` (Boolean) Run two instances with a synchronous standby. Can be turned on or off in place. Default `false`.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))
- `version` (String) Engine major version, e.g. `18`. When unset, the platform default is used and recorded here. Major version upgrades are not available yet, so changing the version of an existing database fails the plan.

### Read-Only

- `created_at` (String) Timestamp when the database was created.
- `current_version` (String) Full engine version running, e.g. `18.0`.
- `etag` (String) Resource version used for optimistic locking during updates.
- `phase` (String) Current phase: Pending, Provisioning, Running, Upgrading, Degraded or Terminating.
