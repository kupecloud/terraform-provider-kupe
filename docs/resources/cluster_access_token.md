# kupe_cluster_access_token (Resource)

Manages an access token for a Kupe cluster: a Kubernetes token and a ready-to-use kubeconfig for CI, and anything else that runs `kubectl` or a Kubernetes client without a person signed in. Create waits until the platform has issued the token, then collects the token and kubeconfig once; the platform never shows them again.

A token never changes in place: changing any argument replaces it with a new token. It stops working when it expires, when it is revoked and when its cluster is deleted; once the platform has removed it, the next plan creates a new one. Removing the member who created it does not revoke it. Only a member with the `admin` role, or an admin API key, can create one. A cluster holds at most 20 access tokens.

### Token in state

Returned only once, when Terraform collects the token during create. It is marked sensitive, which hides it in plan and apply output, but it is stored in Terraform state in plain text, and it gives `admin` access to the cluster. Keep state in an encrypted backend with restricted access, or create tokens outside Terraform.

## Example Usage

```terraform
# An admin token for CI on the cluster "dev"; referencing the cluster orders
# this create after it. Its token and kubeconfig are in Terraform state: keep
# state in an encrypted backend with restricted access.
resource "kupe_cluster_access_token" "ci" {
  cluster      = kupe_cluster.dev.name
  display_name = "GitHub Actions"
  access = {
    role = "admin"
  }
  expires_in_days = 30
}

output "ci_kubeconfig" {
  description = "Kubeconfig for CI. Store it in your CI system's secret store."
  value       = kupe_cluster_access_token.ci.kubeconfig
  sensitive   = true
}
```

### Write the kubeconfig to a CI secret

Pass the kubeconfig straight to your CI system's secret store, so CI jobs run `kubectl` without anyone handling the token. With the GitHub provider, for example:

```terraform
resource "github_actions_secret" "kubeconfig" {
  repository      = "deploy"
  secret_name     = "KUBECONFIG_DEV"
  plaintext_value = kupe_cluster_access_token.ci.kubeconfig
}
```

The CI job writes the secret to a file and points `KUBECONFIG` at it.

### Renew a token

A token never changes in place. When it expires, the platform removes it, and the next `terraform plan` shows it being created again, with a new token and kubeconfig. Until then a refresh warns that it has expired. To renew earlier, change `display_name` or `expires_in_days`, or run `terraform apply -replace=kupe_cluster_access_token.ci`.

A replacement revokes the old token before it creates the new one, so for a while CI has no working credential. For a token CI depends on, create the new one first:

```terraform
resource "kupe_cluster_access_token" "ci" {
  # ...

  lifecycle {
    create_before_destroy = true
  }
}
```

The old token is revoked once the new one is collected and anything that reads its `kubeconfig` (such as the CI secret above) has been updated. Both count toward the cluster's limit of 20 access tokens while the replacement runs.

### Keep the token out of state

`token` and `kubeconfig` are stored in Terraform state in plain text; marking them sensitive only hides them in plan and apply output. The platform shows them once, when Terraform collects them during create, and never again: Terraform keeps them in state and never collects again. If an apply stops after the token is created but before it is collected, the token stays in state, marked tainted, and the next apply replaces it. If your state backend is not encrypted and access-controlled, create the token outside Terraform instead, and store the kubeconfig in your CI system's secret store.

## Import

Import is supported using the following syntax:

```shell
# <cluster>/<id>. The token and kubeconfig cannot be read back: they are null
# after import.
terraform import kupe_cluster_access_token.ci dev/cat-0a1b2c3d4e5f6a7b
```

An imported token's `token` and `kubeconfig` cannot be read back: they are null after import. To get a credential in state, replace the token with `terraform apply -replace=kupe_cluster_access_token.ci`.
