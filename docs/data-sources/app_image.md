# kupe_app_image (Data Source)

Resolves an image tag or digest to an immutable sha256 reference through the Kupe API. Use `reference` as `kupe_app_environment.web.image`. Every read resolves the image again, so a moving tag can change the next plan and deploy on apply. The provider sends no registry credentials.

## Example usage

```terraform
data "kupe_app_image" "web" {
  image = "ghcr.io/kupecloud/hello-kupe:1.5.1"
}

output "image_reference" {
  description = "Immutable image reference for kupe_app_environment.web.image."
  value       = data.kupe_app_image.web.reference
}
```

## Image resolution

The Kupe API resolves the image, from your tenant's container registry or a public registry the platform allows. It checks that the image supports linux/amd64 and runs as a numeric non-root user. The provider only talks to the Kupe API and sends no registry credentials.

For a multi-platform image, `reference` keeps the image index digest; for a single-platform image, the manifest digest. `platforms` is the API's summary, as `os/architecture` or `os/architecture/variant`, and can leave out platforms the image supports. `user` and `exposed_ports` describe the linux/amd64 image.

Every read resolves the image again. Pin a version tag in production: a moving tag such as `latest` can change the next plan, and applying that plan deploys the new digest. Pass a digest to keep the image fixed.

An error on `image` includes the API's refusal code and message. A temporary failure adds a hint to retry, with the delay in seconds when the API sends a numeric Retry-After. Apps must be enabled on the platform to resolve an image.

When Apps are switched off, this data source fails during planning, a destroy plan included. To plan or destroy, replace `data.kupe_app_image` in your configuration with the image digest reference from Terraform state, and remove the data source block so Terraform stops trying to resolve the image.

## Schema

### Required

- `image` (String) Image tag or digest, from your tenant's container registry or a public registry the platform allows.

### Read-Only

- `exposed_ports` (List of Number) TCP ports the linux/amd64 image exposes, as returned by the API.
- `platforms` (List of String) Platforms the API reports, as `os/architecture` or `os/architecture/variant`. The list can leave some out; a successful resolution confirms linux/amd64 support.
- `reference` (String) Immutable image reference with the registry host and `@sha256:` digest. For an image index, this is the index digest.
- `user` (String) Numeric non-root user the linux/amd64 image runs as, as checked by the platform.
